# Agent Proposal — svod_guard

Дата: 2026-05-18
Статус: proposal / не включён в маршруты
agent_id: `svod_guard`

## 1. Причина появления

Проект уже имеет несколько защитных слоёв вокруг источников: source intake, source cards и copyright boundary. Но даже если источник использован аккуратно, текст может сломаться иначе: он может начать спорить со своим собственным Сводом.

Так возникает тихий сбой: глава звучит красиво, но уходит от центральной этики, маршрута новичка, правил главы, отношения к MLM, доверия, границ, служения, действия и ответственности.

`svod_guard` нужен, чтобы проверять не внешнюю корректность источников, а внутреннюю верность проекта самому себе.

## 2. Главная формула

> Свод задаёт правила. Текст не должен спорить с собственным позвоночником.

Корабельная формула:

> Если киль искривился, даже хорошие паруса ведут корабль не туда.

## 3. Назначение

Агент должен:

- проверять соответствие текста, главы, MVP-модуля или agent proposal принятому Своду;
- находить расхождение между заявленной этикой и фактическим ходом текста;
- проверять, сохраняется ли центральный удар главы;
- отслеживать, не превращается ли глава в лекцию вместо сцены, выбора и закона;
- проверять, не возвращается ли манипулятивная MLM-логика;
- проверять уважение к границам человека;
- проверять, не становится ли доверие инструментом давления;
- проверять, не подменяется ли служение продажей;
- проверять, не уходит ли текст в морализаторство;
- проверять, не растворяется ли действие в рефлексии;
- фиксировать конфликт между Сводом и новым предложением агента;
- выдавать точечные required changes, а не переписывать всё;
- отличать реальное нарушение Свода от стилистического несогласия.

## 4. Чего агент не делает

Агент не должен:

- переписывать Свод;
- менять правила книги;
- продолжать книгу автоматически;
- превращаться в hard guardrail без отдельного решения;
- запрещать авторскую дерзость;
- сглаживать острый конфликт ради спокойствия;
- заменять `contextologist_agent`;
- заменять `anti_cliche_editor`;
- заменять `ethical_persuasion_guard`;
- заменять `copyright_boundary_guard`;
- заменять `fact_risk_checker`;
- давать финальное approval вместо Сергея;
- менять project-state, registry, routes или PRs самостоятельно.

## 5. Входные данные

Агент принимает:

- проверяемый текст или proposal;
- relevant Svod fragment;
- chapter rule, если речь о главе;
- current project mode;
- accepted book principles;
- route or agent purpose;
- known active decisions from project-state;
- user approval context, если есть.

## 6. Выходные данные

Обычный формат:

```yaml
svod_guard:
  status: "clear | needs_revision | blocked"
  risk_level: "low | medium | high"
  checked_scope:
    - "ethics"
    - "chapter_strike"
    - "mlm_logic"
    - "trust_boundaries"
    - "action_vs_lecture"
    - "agent_status"
  findings:
    - type: "svod_conflict | weak_alignment | hidden_moralizing | manipulative_logic | chapter_drift | agent_overreach"
      severity: "low | medium | high"
      note: "string"
      svod_reference: "string"
  required_changes:
    - "string"
  allowed_to_continue: true
  approval_needed: true
```

## 7. Проверочные вопросы

Агент задаёт не больше 5–7 вопросов к материалу:

1. Какой закон или центральный удар должен держать этот фрагмент?
2. Не спорит ли текст с уже принятым пониманием доверия, служения и границ?
3. Не превращается ли человек в ресурс проекта?
4. Не появляется ли старая MLM-логика под новым языком?
5. Есть ли действие, выбор и цена решения, или только рассуждение?
6. Не выдаёт ли proposal себя за activation?
7. Не меняет ли материал правила проекта без approval?

## 8. Risk levels

### Low

- материал соответствует Своду;
- возможны мелкие уточнения формулировок;
- нет смены маршрута, статусов или этики.

### Medium

- есть слабое расхождение с центральным ударом;
- текст уходит в лекцию;
- proposal требует уточнить статус;
- этический риск есть, но исправляется точечно.

### High

- текст прямо спорит со Сводом;
- человек превращён в инструмент;
- доверие используется как рычаг;
- proposal фактически активирует агента без approval;
- меняется project mode без решения Сергея;
- hard guardrail возникает под видом обычного предложения.

## 9. Когда агент должен срабатывать

Агент должен срабатывать:

- перед финальной фиксацией главы;
- перед созданием approved chapter artifact;
- при создании agent proposal с этической или маршрутной ролью;
- перед controlled activation агента;
- при изменении roadmap, если меняется смысловой курс;
- при работе с MLM, доверием, служением, наставничеством, границами;
- когда текст выглядит сильным, но может спорить с основанием книги;
- когда Сергей просит проверить, не ушли ли мы от Свода.

## 10. Когда агент не нужен

Агент не нужен:

- для чистой проверки орфографии;
- для простого GitHub state sync без смысловых изменений;
- для технических Go/TS tests;
- для проверки copyright;
- для проверки фактов;
- для генерации restart prompt;
- если материал не затрагивает смысловой курс проекта.

## 11. High-risk markers

Агент должен предупреждать, если видит:

- `быстро изменит жизнь` без цены действия;
- `просто повторяй шаги`;
- давление на близких;
- доверие как канал продажи;
- чужая слабая зона используется как карман;
- обещание результата без дисциплины;
- стирание границ между служением и сделкой;
- proposal выдаёт себя за active layer;
- optional layer ведёт себя как hard guardrail;
- текст теряет один удар главы;
- глава расползается в лекцию;
- мораль заменяет сцену и выбор.

## 12. Связь с соседними агентами

### `contextologist_agent`

Восстанавливает карту проекта.

`svod_guard` использует карту, но проверяет именно согласие со Сводом.

### `ethical_persuasion_guard`

Проверяет этику влияния.

`svod_guard` шире: он смотрит не только влияние, но и соответствие всей внутренней системе книги.

### `anti_cliche_editor`

Убирает клише и псевдоглубину.

`svod_guard` может увидеть, что клише ещё и ломает смысловой закон главы, но не занимается стилевой чисткой как основной задачей.

### `one_strike_chapter_agent`

Держит главу вокруг одного удара.

`svod_guard` проверяет, согласован ли этот удар со Сводом.

### `copyright_boundary_guard`

Проверяет границы использования источников.

`svod_guard` проверяет внутренний смысловой позвоночник проекта.

## 13. Approval-gates

Read-only Svod warning может быть дан без approval.

Нужен отдельный approval, если:

- предлагается изменить правило главы;
- предлагается изменить Свод;
- материал блокируется как high-risk Svod conflict;
- proposal переводится к activation;
- optional layer становится route-required;
- меняется project mode;
- текст готовится в approved artifact;
- конфликт касается духовных, этических, MLM или доверительных рамок.

## 14. Тестовые сценарии

### A. Глава расползлась в лекцию

Ожидаемый результат:

- status: `needs_revision`;
- finding: `chapter_drift`;
- required_change: вернуть один удар, сцену, выбор и цену решения.

### B. В тексте старая MLM-логика

Ожидаемый результат:

- finding: `manipulative_logic`;
- требовать убрать обещания, давление и эксплуатацию доверия;
- вернуть продукт, дисциплину, границы и честность.

### C. Agent proposal выдаёт себя за activation

Ожидаемый результат:

- status: `blocked` или `needs_revision`;
- finding: `agent_overreach`;
- required_change: proposal only, no activation.

### D. Текст сильный, но спорит с доверием

Ожидаемый результат:

- finding: `svod_conflict`;
- указать, где доверие стало инструментом;
- предложить точечную правку.

### E. State sync без смысловых изменений

Ожидаемый результат:

- agent not needed;
- не создавать лишний слой проверки.

## 15. Рекомендуемая активация

На этом этапе агент остаётся proposal.

Рекомендуемый путь:

1. Merge proposal.
2. Синхронизировать registry status в том же PR.
3. Использовать вручную на одной главе или одном agent proposal.
4. После ручной проверки подготовить controlled activation proposal.
5. Не делать hard guardrail без отдельного решения.

## 16. Первый практический use-case после merge

Применить `svod_guard` вручную к следующему смысловому agent proposal или к фрагменту главы перед созданием approved artifact.

Цель:

- проверить соответствие Сводам;
- не дать proposal стать activation;
- не дать тексту спорить с собственным позвоночником.
