# Living Project Docs Audit — первая волна

Дата аудита: 2026-05-17
Статус: proposal / требует пользовательской проверки перед изменением реестров
Контур: living project docs, правила проекта и подготовка агентных слоёв

## 1. Назначение

Этот аудит фиксирует первую проверку загруженных проектных документов. Это не внешние книги и не доказательная база. Это живые документы проекта: Свод, MVP, карта контекстов, профиль взаимодействия, Плотниковский мотор и художественное проектирование главы.

Главное правило: living document может быть важнее внешнего источника, потому что он задаёт правила применения всех внешних источников.

## 4. Предохранители

1. Living docs не надо цитировать в читательском тексте.
2. Эти документы управляют процессом, но не становятся частью книги как служебные блоки.
3. Свод имеет более высокий приоритет, чем внешние книги.
4. Плотниковский мотор усиливает действие и анти-водяной напор, но не отменяет этику Свода.
5. Профиль взаимодействия помогает работать быстрее и точнее, но не должен превращаться в психологический диагноз пользователя.
6. Художественное проектирование главы 30 нельзя путать с финальным текстом главы.
7. Карта контекстов помогает восстановить систему проекта, но не заменяет актуальные решения пользователя.

## 5. Что делать сейчас

Минимальный безопасный PR:

1. добавить этот audit artifact;
2. создать карточки:
   - `plotnikovsky_motor_project_rule`;
   - `interaction_profile_v1_card`;
   - `chapter_30_design_artifact`;
3. не менять пока реестры массово;
4. после approval отдельным PR зарегистрировать новые карточки и обновить location entries для существующих living docs.

## 6. Агентные последствия

После регистрации living docs можно точнее проектировать агентов:

- `plotnikov_motor` как редакторский слой уже существует по смыслу, но его источник нужно отделить от сырого Плотникова;
- `source_intake_auditor` должен проверять living docs до создания новых тематических агентов;
- `socratic_lantern_agent` должен учитывать не только сократические книги, но и художественное проектирование главы 30;
- `influence_ethics_guard` должен учитывать главу 31 и обновления из Paket v20;
- будущие агенты не должны конфликтовать со Сводом v4.1.

## 7. Следующее решение

После review этого PR можно:

- зарегистрировать новые source cards в `sources.registry.json`;
- обновить `source-locations.registry.json` для living docs;
- затем перейти к первому тематическому agent proposal.
