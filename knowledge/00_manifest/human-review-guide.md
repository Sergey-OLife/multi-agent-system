# Human Review Guide

Этот файл нужен для ручной проверки смысловых артефактов, которые создают агенты. Он не заменяет approval пользователя и не разрешает автоматически переходить к черновику главы.

## Где искать файлы в GitHub

1. Откройте репозиторий `Sergey-OLife/multi-agent-system` в GitHub.
2. Убедитесь, что выбрана актуальная рабочая ветка или PR, который нужно проверить.
3. Основные файлы для проверки находятся в папках:
   - `knowledge/04_processed/plotnikov_map/` — карты обработки источника;
   - `knowledge/02_project_rules/sync_packages/` — пакеты синхронизации источника с нашей будущей главой;
   - `knowledge/05_agent_memory/review_queue/` — индекс очереди ручной проверки;
   - `knowledge/00_manifest/` — состояние проекта и инструкции для человека.

## Как открыть файл через Go to file

1. В верхней части страницы репозитория нажмите **Go to file**.
2. Введите путь файла, например `knowledge/05_agent_memory/review_queue/review-index.md`.
3. Выберите найденный файл из списка.
4. Читайте файл прямо в GitHub или откройте вкладку **Raw**, если нужно скопировать содержимое без оформления.

## Что проверять в Plotnikov map

Для файла `knowledge/04_processed/plotnikov_map/plotnikov_chapter_00_preface_map.md` проверьте:

- карта фиксирует функцию материала, а не пересказывает предисловие;
- нет длинных цитат и близкого рерайта;
- смысловые разделы написаны по-русски;
- технические ключи metadata могут оставаться на английском;
- ясно указано, что можно сохранить как функцию: входной договор, отказ от чудо-обещаний, уважение к скепсису, переход к действию;
- ясно указано, что нельзя копировать: биографию, достижения, порядок аргументов, риторику и заметные метафоры источника;
- этические риски и финансовые ограничения сформулированы трезво;
- `next_working_point` не разрешает создавать `chapter draft` без явного approval пользователя.

## Что проверять в sync package

Для файла `knowledge/02_project_rules/sync_packages/sync_chapter_00_preface.md` проверьте:

- sync package связывает функцию источника с самостоятельной будущей главой, а не пересказывает источник;
- целевая функция `chapter_00_preface` понятна по-русски;
- перечислено, что проект берёт только как функцию, а что не берёт;
- guardrails запрещают финансовые гарантии, давление достижениями, рекрутинговый голод и смешение духовного пространства с бизнесом;
- `synthesis_layers` опираются на существующие source ids и объяснены по-русски;
- `next_working_point` разрешает следующий шаг только после явного пользовательского approval карты и sync package.

## Когда можно переходить к chapter draft

Переход к `chapter draft` разрешён только после того, как пользователь явно подтвердил, что проверил и одобрил оба файла:

- `knowledge/04_processed/plotnikov_map/plotnikov_chapter_00_preface_map.md`;
- `knowledge/02_project_rules/sync_packages/sync_chapter_00_preface.md`.

Формулировка approval должна быть явной: например, «одобряю карту и sync package для chapter_00_preface, можно создавать chapter draft». Молчание, отсутствие замечаний, общий комментарий «нормально» или техническое прохождение тестов не являются approval.

## Что нельзя утверждать без явного approval пользователя

Без явного approval пользователя нельзя утверждать, что:

- карта Плотникова принята как финальная;
- sync package принят как финальный;
- можно создавать `chapter draft`;
- `chapter draft` уже проверен редакционно;
- можно создавать `reviewed chapter`;
- можно создавать `approved chapter`;
- будущий текст главы утверждён для книги;
- пользователь согласился на спорные этические, финансовые или стилистические решения.

Каждый переход между стадиями должен быть отдельным и явно разрешённым пользователем.
