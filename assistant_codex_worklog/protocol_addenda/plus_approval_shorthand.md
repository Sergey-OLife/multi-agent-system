# Protocol Addendum — plus / approval shorthand

Дата фиксации: 2026-05-17
Статус: обязательное рабочее правило после merge

## 1. Правило

Сергей вводит короткие команды:

```text
+
```

означает: продолжай следующий логичный шаг по текущему плану.

```text
++
```

означает: approval для текущего открытого approval-gate и разрешение выполнить следующий ожидаемый merge/approval action.

## 2. Как трактовать `+`

`+` не является approval.

При `+` можно:

- продолжить анализ;
- открыть следующий безопасный PR;
- подготовить proposal;
- проверить mergeability;
- сделать следующий технический шаг, если он не требует approval;
- дать конкретное предложение по дальнейшему действию.

При `+` нельзя:

- мержить PR;
- включать агента в маршруты;
- менять hard guardrails;
- выполнять checkpoint full;
- считать спорное решение утверждённым;
- создавать irreversible changes без отдельного approval.

## 3. Как трактовать `++`

`++` означает явный approval, если в чате есть один понятный текущий approval-gate.

При `++` можно:

- смержить текущий PR, который уже был представлен на review;
- принять proposal, если именно он был текущим approval-gate;
- выполнить следующий merge/approval action, если он был явно ожидаемым.

## 4. Когда `++` недостаточно

Если одновременно есть несколько открытых approval-gates, `++` требует уточнения.

Пример:

```text
Сейчас есть два approval-gates: PR #41 и активация агента. Уточни, что утверждаем.
```

Также `++` не заменяет отдельное approval для:

- `#checkpoint full`, если предварительный restart prompt ещё не отправлен;
- hard guardrail activation;
- массовых изменений реестров;
- удаления файлов;
- изменения приватных/безопасностных правил;
- действий, где пользователь явно просил сначала согласовать детали.

## 5. Приоритет

Это правило не отменяет существующие approval gates. Оно только сокращает форму команды.

`+` = двигайся дальше без утверждения.

`++` = утверждаю текущий ожидаемый approval-gate.

## 6. Обязательная интерпретация в ответах

На `+` отвечать не надо длинным пересказом. Нужно сразу делать следующий безопасный шаг.

На `++` перед merge/action нужно проверить:

- какой именно PR/action сейчас ожидает approval;
- mergeability, если речь о PR;
- changed files, если речь о merge;
- нет ли нескольких конкурирующих approval-gates.

После действия дать короткий отчёт: что утверждено, что сделано, какой следующий шаг.
