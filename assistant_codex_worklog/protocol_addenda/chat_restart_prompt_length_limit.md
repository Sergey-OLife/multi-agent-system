# Protocol Addendum — chat restart prompt length limit

Статус: обязательное рабочее правило
Дата фиксации: 2026-05-17

## 1. Правило

Перед `#checkpoint full` ChatGPT сначала присылает Сергею restart prompt прямо в чате.

Этот **чатовый restart prompt** должен быть не длиннее **6000 знаков с пробелами**.

Ограничение относится только к тексту, который отправляется Сергею в чат для копирования в новый чат.

Ограничение **не относится** к файлу:

`assistant_codex_worklog/restart-prompt.md`

Файл `restart-prompt.md` может быть подробным рабочим документом. Чатовый prompt — это не архив проекта, а компактный стартовый ключ.

## 2. Как сохранять смысл при лимите

Лимит достигается не выкидыванием смысла, а заменой длинных вставок ссылками, путями и короткими указателями.

Правильная задача чатового prompt:

> Не перенести весь проект в новый чат, а точно указать, какие файлы открыть, где стоит работа, что делать первым и чего нельзя делать.

Если смысл не помещается в 6000 знаков, нужно не раздувать prompt, а вынести подробности в GitHub-файлы и сослаться на них.

## 3. Что нельзя вставлять в чатовый restart prompt

Запрещено вставлять:

- большие фрагменты книги;
- длинные принятые сцены;
- полный пересказ текущей главы;
- подробные описания всех агентов;
- историю всех PR;
- длинные методологические объяснения;
- содержимое `project-state.md`, `roadmap.md`, `current-state.md` или `working-protocol.md`;
- большие цитаты из источников;
- сырой текст книг или источников.

По книге допустимо вставить только **1–2 предложения последнего принятого текста**, если без них невозможно продолжить сцену.

## 4. Что должно быть в чатовой версии

Минимальный состав restart prompt:

1. Репозиторий и принцип: GitHub — источник правды, не память старого чата.
2. Файлы, которые нужно открыть первыми.
3. Текущая версия / последний merged PR.
4. Текущий режим: Book Fast Track, Strict PR Workflow, Source Intake Audit или другой.
5. Активные запреты и approval-gates.
6. Текущий незавершённый фокус.
7. Первый следующий шаг после рестарта.
8. Короткий фрагмент книги — только если он нужен для продолжения.

## 5. Как сокращать без потери управления

Сокращать так:

- вместо описания агента давать `agent_id`, статус, формулу и главный запрет;
- вместо истории PR давать последний merged PR и максимум 2–4 последних PR одной строкой, если это реально важно;
- вместо длинного фрагмента главы давать 1–2 предложения и путь к файлу;
- вместо объяснения правил давать правило + действие;
- вместо пересказа project-state писать: `Открыть knowledge/00_manifest/project-state.md`;
- вместо повторения протокола писать: `Открыть assistant_codex_worklog/working-protocol.md и protocol_addenda/*.md`.

## 6. Обязательная проверка перед отправкой

Перед отправкой чатового restart prompt ChatGPT должен проверить:

- текст помещается в 6000 знаков с пробелами;
- нет больших книжных вставок;
- нет сырого текста источников;
- есть первый следующий шаг;
- есть запрет восстанавливать контекст по памяти старого чата как главному источнику;
- есть указание открыть GitHub-файлы-якоря;
- нет противоречия с `restart_prompt_before_checkpoint.md`.

Если prompt получается длиннее 6000 знаков, ChatGPT обязан сократить его до отправки Сергею.
