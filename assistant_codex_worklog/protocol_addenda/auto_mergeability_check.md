# Protocol Addendum — automatic mergeability check

Дата фиксации: 2026-05-17
Статус: обязательное рабочее правило после merge

## 1. Правило

Перепроверка mergeability открытого PR не требует отдельного подтверждения Сергея.

Если PR уже открыт и ожидает review/approval, ChatGPT должен сам перепроверять mergeability перед тем, как просить `++` или выполнять merge по `++`.

## 2. Когда проверять автоматически

Проверять mergeability без запроса пользователя:

- сразу после создания PR, если GitHub сначала вернул `mergeable: false` или промежуточное состояние;
- перед сообщением, что PR готов к approval;
- после команды `+`, если текущий безопасный следующий шаг — проверить PR;
- после команды `++`, перед merge;
- если PR был открыт несколько шагов назад и его статус мог измениться.

## 3. Что не считается approval

Автоматическая проверка mergeability:

- не является approval;
- не разрешает merge;
- не разрешает включение агента в маршруты;
- не отменяет approval-gates;
- не заменяет `++`.

## 4. Что делать после проверки

Если PR mergeable:

```text
PR #N mergeable: true. Для merge нужен ++.
```

Если PR не mergeable:

```text
PR #N пока не mergeable. Проверяю/устраняю причину, если это безопасно. Если требуется решение Сергея — обозначаю конкретно.
```

## 5. Связь с plus shorthand

`+` может запускать автоматическую проверку mergeability.

`++` сначала запускает automatic mergeability check, затем merge, если:

- есть один понятный approval-gate;
- PR mergeable;
- changed files проверены;
- нет конфликтующих approval-gates.

## 6. Запрет

Нельзя просить у Сергея отдельное подтверждение только для перепроверки mergeability.

Подтверждение нужно для решения, а не для технической проверки статуса PR.
