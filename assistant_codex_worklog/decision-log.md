# Decision Log — Assistant × Codex

Этот журнал фиксирует ключевые решения нашего рабочего процесса с Codex.

## Решения

### 1. Не начинать новый чат с нуля

Решение: создать отдельную папку `assistant_codex_worklog/`, не связанную напрямую с книгой.

Назначение: сохранить контекст взаимодействия Сергей ↔ ChatGPT ↔ Codex.

### 2. Отделить работу с Codex от книги

Решение: эта папка не хранит главы, карты Плотникова как source artifacts, raw books или материалы будущей книги.

Она хранит только рабочий слой управления Codex-задачами.

### 3. Главный источник правды — GitHub

Решение: новый чат восстанавливается по файлам репозитория, а не по памяти старого чата.

### 4. Все ответы с файлами должны содержать кликабельные ссылки

Решение: вместо голых путей давать ссылки на GitHub-файлы.

### 5. Новая задача или текущий чат Codex

Решение:

- если PR смержен — следующая веха обычно новая задача Codex;
- если PR открыт и правим замечание reviewer — это ответ в текущий Codex-чат;
- если Codex сделал работу, но PR не виден — нажать `Создать PR` в той же задаче.

### 6. Google Drive для исходников

Решение на паузе: полные материалы загрузить в приватный Google Drive и связать через source location registry.

Не грузить raw books в GitHub.

### 7. Текущий следующий шаг

После `v1.4 Add clickable review links` следующий ручной шаг:

- открыть Review Index;
- проверить Plotnikov Map и Sync Package по `chapter_00_preface`;
- дать approval / правки / reject.

### 8. Введена команда checkpoint

Решение: команда `#checkpoint full` означает сохранить полную рабочую точку в `assistant_codex_worklog/`.

При таком checkpoint обновляются:

- `current-state.md`;
- `roadmap.md`;
- `decision-log.md`;
- при необходимости `working-protocol.md` и `restart-prompt.md`.

Назначение: защитить работу от потери контекста при обрыве связи, перерыве, перегрузе чата или переходе в новый чат.
